## 推送 fix/ratelimit-client-ip 到 GitHub（沙箱环境）

### 卡点链路（已逐一解决）
1. **沙箱无法访问 GitHub 凭据**：git credential.helper=manager 指向 PortableGit 的 GCM，但沙箱隔离拿不到 Windows 凭据库；`GIT_TERMINAL_PROMPT=0` 下无交互 → push 卡死 9-10min 无输出（只读 ls-remote 正常，写操作挂起）。
   - 解决：用 URL 注入 PAT：`git -c credential.helper= push "https://x-access-token:<PAT>@github.com/longxiaocao/sakurafilte.git" <branch>`（注意用 `x-access-token:` 前缀，否则 GitHub 报 "Password authentication not supported"）。
2. **GH001 大文件拦截**：分支历史里 commit `b8f64ae` 误提交了 `_tmp/pg_backup_20260816.dump`（657MB），GitHub 预接收钩子拒收（>100MB）。历史里其他最大文件仅 52MB（不触发）。
   - 解决：`git filter-branch --force --index-filter 'git rm --cached --ignore-unmatch _tmp/pg_backup_20260816.dump' -- --branches fix/ratelimit-client-ip`（注意：实际改写波及了 fix/review-gate-issues，因 --branches 参数误匹配；master 未变）。
   - 该 dump 仅在 fix/ratelimit-client-ip 历史；本地 master 不含（master=NO）；远端无该分支（新建，无需 force）。
   - 事后恢复：`git update-ref refs/heads/fix/review-gate-issues refs/original/refs/heads/fix/review-gate-issues`（远端 review-gate-issues=a1a4476 已对齐）。
3. **HTTP/1.1 + postBuffer**：推送加 `-c http.version=HTTP/1.1 -c http.postBuffer=524288000` 规避 curl 65 reset（但真正拦路是 GH001，非网络）。
4. **token 防泄露**：`push -u` 会把带 token 的 URL 写进 `.git/config`。推送后用 `git branch --set-upstream-to origin/fix/ratelimit-client-ip`（先 `git fetch origin` 建跟踪 ref）覆盖掉含 token 的 upstream；复核 `git config --list | grep token` = 0。

### 教训
- 推送前务必先 `git rev-list --all --objects | ...` 排查历史大文件，否则远端 GH001 才暴露。
