# 2026-08-26 工作日志

## 混元审核三个 prod 硬约束 — 核对 + 修复（docker-compose.prod.yml）

关键前提（已核对）：**prod 是单文件部署**（`docker compose -f docker-compose.prod.yml --env-file .env.prod up -d`），不叠加 base。所有部署文档一致。

镜像实测（docker inspect）：
- meilisearch:v1.12 ENTRYPOINT=`["tini","--"]`, CMD=`["/bin/sh","-c","/bin/meilisearch"]` → 直接写 `["--max-indexing-memory",N]` 会让 tini exec 该参数 → **exit 127**（base 即此坑）。
- postgres:16-alpine 默认 max_connections=100；Docker 默认 /dev/shm=64MB。

三处修复（均真实有效）：
1. **postgres**：加 `shm_size: "4gb"`（防并行排序/哈希 No space left on device）+ `command: ["postgres","-c","max_connections=200"]`（防 c100 连接池雪崩）。
2. **meilisearch**：`memory 1G→8G` + `command: ["/bin/meilisearch","--max-indexing-memory","4096"]`（正确二进制路径写法，避 exit 127；1G 必 OOMKill）。
3. **api**：连接串加 `Maximum Pool Size=120;Connection Idle Lifetime=60`（Npgsql 默认 100，与 PG 200 配对）。

附带修复 base（dev，docker-compose.yml）：meili `command` 修正为 `["/bin/meilisearch","--max-indexing-memory","8192"]`（修 exit 127）。

`docker compose -f docker-compose.prod.yml config` 校验通过（exit=0，仅 env 未注入 warning）。

注意：meili 8G 上限需按真实生产机物理内存再调（索引体积≈磁盘，百万级数 GB）。
