## 详情页 1s 延迟治本（17:20，提交 bc04a06）
- 根因链：用户 Network 面板红框 946ms = 详情 API。拆解发现：①GetByIdAsync 4 串行查询（单查询其实 <1ms 快）②**真瓶颈 = GetByOemAsync 匹配查询 Seq Scan 450ms**（EXISTS cross_references + OR 三列，百万行 products 全表扫 cost=9858729；代码注释"~2ms"是万行时代）。
- 修复：匹配查询拆两段（xrefs.oem_no_3 索引 ~16ms → products OR BitmapOr ~2ms）+ GetByIdAsync factory 并发 + 详情缓存 30s。实测冷查询 1150ms → 58-66ms。
- 教训：**OR + correlated EXISTS 组合会废掉索引（Seq Scan）**；写这种查询要么拆段要么验证 EXPLAIN。
- 中间弯路：先试 Task.WhenAll（单 DbContext 非线程安全失效）、再试缓存（只解决重复点击）、factory 并发（查询本身不慢没效果）——最终 EXPLAIN 定位真瓶颈。**性能排查要先用 EXPLAIN 找 SQL 瓶颈，别在应用层猜**。
